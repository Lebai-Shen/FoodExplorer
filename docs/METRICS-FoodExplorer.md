## 1. 这份文档解决什么

PRD 说清楚要做什么，这份文档说清楚怎么衡量它做成没有。它定义四件事：北极星指标、驱动它的输入指标、从打开到付费的转化漏斗、以及埋点事件字典。后面做数据看板、接分析平台，都按这份来。

## 2. 北极星指标

### 2.1 业务类型

FoodExplorer 属于效率型（Productivity）游戏。它的价值是帮店主更快做对一个经营决定。

### 2.2 北极星指标

**每周被采纳的经营建议数（Weekly Adopted Recommendations，WAR）**

定义：一周内，店主点击"我做了"的建议条数。按自然周统计，同一条建议只算一次。

为什么选它：店主采纳一条建议，说明他确实拿到了价值，也说明我们的建议能被读懂、被执行。这个动作会重复发生，是习惯，也是后面愿意付费的前提。

### 2.3 它为什么合格

- 好理解：一句话说清，这周店主采纳了几条建议。
- 以客户为中心：衡量的是店主得到的帮助，不是我们的收入。
- 可持续：反复采纳代表习惯，不是只发生一次。
- 对齐愿景：我们要的是让数据变成行动，采纳就是行动。
- 可量化：就是每周的条数。
- 可影响：把建议写清楚、提高建议质量、简化上传，都能让它变大。
- 领先指标：采纳多的店主更可能留下来，也更可能付费。

### 2.4 输入指标（驱动北极星，5 个）

| 输入指标 | 怎么算（分子 / 分母，按周） | 为什么重要 |
| --- | --- | --- |
| 上传完成率 | 提交数据的店主数 / 进入数据页的店主数 | 没有数据就没有建议 |
| 生成转化率 | 点"开始生成"的店主数 / 提交数据的店主数 | 数据进来后有没有走到生成这一步 |
| 建议访问率 | 看过建议详情的店主数 / 生成过建议的店主数 | 建议有没有被读 |
| 首条建议采纳率 | 采纳过的店主数 / 看过建议详情的店主数 | 建议有没有被信、被执行 |
| 采纳后复访率 | 采纳后 7 天内回来看效果的店主数 / 采纳过的店主数 | 采纳之后有没有形成闭环和习惯 |

### 2.5 健康指标（护栏）

- 建议被标记"不适用"的比例（越高说明建议质量越差）
- 数据上传失败率
- 页面错误率、生成耗时
- 用户反馈和投诉量

### 2.6 业务指标（变现，早期先埋点观察）

- 免费次数用尽后的注册转化率
- 订阅转化率
- 订阅退订率
- 每店主月收入（ARPU）

## 3. 转化漏斗

从第一次打开到付费，一共 8 步。每一步记一次事件，就能看出用户在哪一步流失。

1. 访问（visit）
2. 上传或录入数据（data_submit）
3. 点击生成（generate_click）
4. 查看建议（advice_view）
5. 采纳建议（advice_adopt）
6. 注册登录（register，免费次数用完时触发）
7. 复访验证（return_verify）
8. 订阅付费（subscribe）

每一步的转化率，等于这一步的人数除以上一步的人数。

## 4. 事件字典（埋点）

通用属性每个事件都带：匿名 ID、用户 ID（登录后）、时间、页面、来源渠道、设备类型。

| 事件名 | 触发时机 | 关键属性 | 对应漏斗 / 指标 |
| --- | --- | --- | --- |
| login_view | 打开登录页 | 来源渠道 | 漏斗第 1 步 |
| login_success | 登录成功 | user_id | 注册转化 |
| data_view | 进入数据页 | 是否首次 | 漏斗第 1 步 |
| data_input_start | 开始录入或上传 | 方式（手动 / Excel） | 上传完成率 |
| data_submit | 提交数据（进入预览确认） | 方式、行数、是否报错 | 上传完成率 |
| generate_click | 点"开始生成经营建议" | 剩余免费次数、额度类型（匿名 / 每周） | 生成转化率 |
| generate_success | 生成成功 | 建议条数 | 生成转化率 |
| generate_fail | 生成失败 | 错误原因 | 健康指标 |
| home_view | 进入首页 | 是否有数据 | 漏斗第 4 步 |
| advice_list_view | 进入建议列表 | 建议条数 | 建议访问率 |
| advice_card_click | 点击某条建议 | advice_id、rule_id | 建议访问率 |
| advice_detail_view | 进入建议详情 | advice_id、rule_id | 建议访问率 |
| advice_mark_done | 点"我做了" | advice_id、rule_id、第几次 | 北极星、采纳率 |
| free_quota_exhausted | 匿名免费 3 次用完 | 是否弹注册 | 注册转化 |
| register_success | 注册成功 | 来源（用完额度 / 主动） | 注册转化 |
| return_verify | 采纳后回来看效果 | advice_id、间隔天数 | 采纳后复访率 |
| subscribe_click | 点击订阅 | 套餐 | 订阅转化 |
| subscribe_success | 订阅成功 | 套餐、金额 | 订阅转化 |

当前 demo 里已经打了三个事件：`home_view`、`advice_card_click`、`advice_mark_done`，代码在 lib/track.js。上面这张表是完整版，后面逐个补上。

## 6. 查看节奏与告警

- 每日：错误率、上传失败率、生成失败率（开发 + PM）
- 每周：漏斗各步转化率、输入指标（PM）
- 每月：北极星、业务指标、OKR 进度（整个团队）
- 每季度：校准指标本身是否还合适（策略）

告警示例（触发后 PM 和开发在一个工作日内排查）：生成失败率 > 5%；数据上传失败率 > 10%；采纳率周环比下降 > 20%；免费次数用尽后的注册转化 < 10%。

## 7. 工具建议

- MVP：先用现在的前端埋点加一个简单计数，够看漏斗就行。
- 要看漏斗和留存：接 PostHog（有免费额度，自带漏斗和留存）或 Mixpanel。
- 要做 SQL 报表：Metabase、Looker。
- 错误监控：Sentry。
